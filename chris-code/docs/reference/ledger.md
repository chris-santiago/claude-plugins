# Ledger commands

`ledger.py` is the typed record store behind `subagent-driven-development`, `executing-plans` and `verification-before-completion`. It lives in the SDD skill's `scripts/` directory and is always called through `$SDD_SCRIPTS`, the skill's absolute scripts path. Every command except `diff-since` and `labels` takes `--store DIR`; the default store is `.sdd/` at the repo toplevel.

Commands that write the store hold an exclusive lock on its `.lock` file while they read, check and write, so parallel agents never interleave lines or both pass a check only one of them should. The store doesn't exist until its first write (normally `store-dir`), and only that write runs unlocked. A refusal writes nothing, not even the store.

Records carry schema version 2. A record or store written by an earlier release is refused with a message to finish that run on the release that started it, or to `clear` the store and start over.

## Reading the run

| Command | What it prints |
|---|---|
| `run-state [--plan PLAN]` | First a `Verdict:` line and a `Next:` line: whether the store is `fresh`, a run of this plan to `resume`, a close in progress (`closing`, naming its latest step), a `finished` run, another plan's (`foreign`), or `ambiguous`, and what to do about it. Without `--plan` it judges against the latest plan the store recorded; a `--plan` that doesn't exist exits 2. Then where the run stands: the stage map with each task's state, each task in flight's rounds so far, what's parked for the stage's batched question (an escalation, a held or waiting finding, an open behavior choice), notes owed, open disclosures and questions, the count of blocking items, agent handles, the latest checkpoint, and once the close starts, its steps, rulings and deferrals |
| `read` | The whole store as markdown: every record, then every progress-log entry |
| `open` | What blocks: open record items (`cannot_verify`, `duplication_pending`, escalations, open statuses, a `handed_off` coder whose coder of record hasn't finished that cycle, malformed records), notes tasks in flight haven't received, and open disclosures and questions |
| `completed` | Task ids with a completion entry, one per line |
| `shapes` | Shared symbols the coders declared, as every brief carries them: one line per symbol and path, credited to the earliest task that declared it |
| `stats` | Each task's verdicts cycle by cycle from the check history, the records that flagged `introduced_by_fix` or `recurring`, each triage round by task (kind, coder model, and how many findings it closed, saw survive and saw a fix introduce), and the tests-first `n/a` counts by category |
| `report` | What the completion report lists: user rulings, the open follow-ups grouped by rule as the close batch (fix, file or ignore each), the coders' `unlisted case:` concerns, follow-ups settled during the run, dispositions and waivers, disclosures with where each landed, questions with their rulings, and the tasks that ran light |
| `notes --task N` | The notes task N must receive, marked delivered or not, and the questions it owns |
| `findings <decision-path>` | The finding ids a holistic decision record at that path must account for, and the decisions it must reconcile with |
| `baseline <tree> --task N\|final\|close` | The round a fix baseline starts: its kind, its cycle (the one every coder of the round writes), who re-checks it, the decision doc path for a holistic round, and the findings sent. Errors when the last triage entry before that snapshot isn't a fix round |
| `store-dir` | The resolved store path, creating it and its self-ignoring `.gitignore` if needed |
| `path --task N\|final\|close [--agent NAME] [--kind record\|report\|brief]` | A handoff file's path: `task-N-<agent>`, `final-<agent>`, or `close-<agent>` for the close's gates and coders, as `.json` for a record and `-report.md` for a report; `--kind brief` gives `task-N-brief.md`. Exits 2 on a combination with no file (a brief outside a task, an agent name with a path in it) or a retired scope (`gate`, `ruling`), whose message names `--task close` |

## Routing a task

| Command | What it does |
|---|---|
| `triage --task N\|final\|close` | Turns the scope's records into state changes for its findings, then computes the next step. Every finding is its own run of `finding` entries in the progress log, and its state is its latest entry: `fix`, `sent`, `held`, `waiting`, `note`, `noted`, `filed`, `fixed` or `dropped`. Only a re-check changes a finding: one seen for the first time starts as `note` (S1-S2), `filed` (S1-S2 of contract reach, filed as a follow-up) or `fix` in a task, and at the close as `fix` (an intent not-met, S4+, or a failing commit gate) or `waiting`. After that a record only reports what a re-check saw: a sent finding its rewritten record no longer raises is `fixed`, one still raised is `fix` again, and a contest the raising reviewer concedes is `fixed` and one it holds is `held`. The step: `patch` or `holistic` (contract reach or a `root cause:` concern) sends the `fix` findings. After two such rounds, or after a ruling round, open work goes to the user as `waiting` instead, and the step is `escalate` in a task or `decide` at the close, the same step that comes when only held or waiting findings remain. A finding the user rules `fix` after either starts a `ruling` round, and in a task so does an override logged since an `escalate` or `done` entry. A task's notes or an undelivered note get `polish`; otherwise the step is `done`. At the close an open can't-tell prints `clarify` (re-check `intent`, no round, no snapshot), and `done` is final. Appends the state changes and one triage entry, files the loop's deferrals as follow-ups (S1-S2 contract-reach findings, notes a coder skipped, sites a sweep found outside the scope, root causes a decision excluded), and prints the step, who re-checks it (`raising`, `all`, `spec` after an override's ruling round, `gate`, or `none`), each sent finding's id, tier and rule, the held and waiting findings with the `rule` command that settles them, the decision doc a holistic round writes, a re-run-the-gate line when a gate finding was sent, and the settled ids. A `patch`, `polish` or `ruling` step whose every finding is one site (reach `local`) of S3 or less, none a gate's or an intent not-met, and with no `root cause:` concern, is marked `inline` and prints a line asking the orchestrator to offer the user an inline fix. A fix step (`patch`, `holistic`, `ruling`, `polish`) also snapshots the working tree right after its entry and prints `Fix baseline: <tree>` and `Task files: <paths>` for the dispatch. A `root cause:` concern a decision chooses to fix (once its round's fix finishes, unless the user discards it) or excludes, or the user waives, stops counting. A fix step's round lasts until its coder has finished (a `done` coder record carries its baseline) or the orchestrator logged an `inline` fix from that baseline, at `final` and `close` until `commit` has landed the fix, and until the raiser of each finding it sent has written its record again (a re-check, or a new `gate` run for a gate finding), as has every other record it named (every reviewer after a holistic round, the spec reviewer after an override's ruling round). A round whose every sent finding (a polish round: its notes) the user has filed or dropped waits only for `discard` of its unlanded changes. Until then, or with nothing changed, triage reprints that entry and its baseline with what it is waiting for and logs nothing. A record counts as re-checked by being written, so a re-check with the same content still counts. A store triaged before findings had entries is seeded from its triage entries once. Refuses, writing nothing, while a record in scope is malformed or when the scope has no reviewer record. A ruling on the mutation gate starts no round |
| `ready --task N\|final [--light]` | Lists every blocker to a commit and exits 1 while any remains: triage not at `done`, a held or waiting finding, a finding still awaiting its re-check, an open behavior choice, an undelivered note, an open disclosure or question the task owns, an open `cannot_verify`, a first attempt's handoff whose coder of record hasn't finished, a malformed record, and at `final` an open escalation or `duplication_pending`. A task's own decision escalations aren't open items: the coder contests them. `--light` is executing-plans' path and skips only the triage, held and open-choice checks |
| `gate --task N\|final --test CMD [--lint CMD]` | Stages every change under the scope's footprint (at `final`, every task's files plus the files its coders changed), runs labels on the staged lines, then lint, then the task's `Verify:` command, each passing only on exit 0, and writes a gate record. Refuses when the scope has no recorded footprint, or a task's footprint has no change (at `final` and `close` it gates HEAD instead). The test finding's text never carries the run's output, so the same failure keeps its id. Exits 0 on pass, 1 on fail. A labels or lint failure returns to the coder as the same attempt. A test failure becomes one S3 local finding over the scope's files and enters triage |

## Writing the run

| Command | What it does |
|---|---|
| `note --kind KIND --text "..." [--for N] [--owner N\|close] [--from N\|final\|run] [--rule TEXT]` | Files an orchestrator note and prints its id. Kinds: `task-note` (`--for` a task), `run-note`, `disclosure` and `question` (`--owner` a task or `close`), `follow-up` (`--rule` is the rule it falls under, which `report` groups by), `disposition`, `checkpoint` |
| `notes --task N --deliver` | Records that the session (not a brief) delivered every note the task requires |
| `notes --task N --waive ID --reason "..."` | Records that a required note doesn't apply to the task, with why |
| `stage --task N --stage K --files PATH...` | Records a task's stage and file footprint; refuses a path another unfinished task in the same stage claims. `stage --task final --files PATH...` (or `--task close`) adds files to that scope's footprint, for a fix outside every task |
| `handle --task N\|final --role NAME --agent ID` | Records the agent id behind a task's role, so it can be continued after a compaction |
| `commit --task N\|final\|close --message "..." --test CMD [--lint CMD] [--light]` | Takes a ready scope to a completed commit and exits 1 at the first step that stops it: the `ready` blockers (nothing staged), a coder file outside a task's footprint, the gate (skipped when the last passing gate checked these same files), `git commit` of the footprint alone with the message verbatim (other staged paths stay staged), then `complete` with `commits <before7>..<after7>`, which deletes the scope's scratch copies and build caches. At `final`, a fix the coder has finished is committed for its re-check without `ready` or `complete`, and at `done` with nothing left uncommitted it gates HEAD and completes without a commit. At `close` it commits only a finished close fix, for its re-check, and completes nothing: the close finishes when its triage prints `done`. At `final` and `close` a fix's commit logs the files its coder changed into the scope's footprint (so a file from an earlier attempt stays in) and logs the fix as landed, which its triage waits for. A failing gate there goes back to the coder as the same attempt, and a fix that changed nothing lands without a commit once the gate passes on HEAD. The gate is skipped only when the last passing gate checked the same files, staged the same way, with the same test and lint commands; a file the gate's commands rewrote stops the commit until it is gated again. A refused `complete` after the commit reports the commit, which is never undone |
| `append --type progress\|complete --task N\|final\|close\|run --note "..." [--light]` | A progress note or a task's completion (`commit` appends the completion itself). `--task close` is for rulings about the close (the mutation-gate answer; its findings are ruled with `rule`), and `--task run` for rulings about the whole run. `complete` re-runs `ready` and refuses without a passing gate whose staged tree matches the committed blobs of the scope's files. `--light` is executing-plans' path and is recorded on the entry, so `report` shows which tasks ran light. `--type complete --task close` is refused: the close finishes when its triage prints `done` |
| `rule ID... --as fix\|file\|drop --note "user ruling: ..."` | Records the user's ruling on reviewer or gate findings, in a task or at the close, as each finding's next entry. `fix` puts it back to be fixed (the next triage starts a ruling round), `file` files it as a follow-up carrying its id, raising record and report path, and `drop` settles it. A later ruling replaces an earlier one, and moving a finding off `filed` resolves its follow-up. Checks every id before writing anything, and refuses an id no record in scope raised, a finding already fixed, `fix` on a finding a round has already sent, a finding of a completed task, and any finding once the close is done. A finding a record raises that triage hasn't seen yet takes its data from the record |
| `inline --task N\|final\|close --note "user ruling: ..." [--files PATH...]` | Logs that the orchestrator fixed the scope's latest round itself, on the user's ruling, in place of a coder. It finishes the round as a coder's finished fix would, and the next fix step's cycle comes after it. The commit (at `final` and the close) and the re-checks follow as for any fix, and the round counts toward the cap. Refuses a step triage didn't mark `inline`, a round already finished or ruled off, a note that isn't the user's ruling, and a fix that changed nothing since the round's baseline. `--files` names changed files outside the scope's footprint, at `final` and the close only; a task's footprint grows by `stage`. `report` lists it with the rulings |
| `discard --task N\|final\|close` | Ends a round the user ruled off (every finding it sent filed or dropped): puts the files it changed and never landed back to the round's `Fix baseline`, so the work before the round stays, removes the scope's gate record, which judged the discarded work, and logs the discard. Refuses a round that still has work, and one with nothing to discard |
| `resolve ID [--note "..."]` | Closes an open item or note. Escalations and questions need `user ruling: ...`, and so do an intent statement still can't-tell (`close-intent-reviewer#statements[<n>]`), a coder's open behavior choice, and a coder's `root cause:` concern, which only the user settles (waived, accepted or overridden). A reviewer or gate finding is refused: the user rules it with `rule`. A disclosure's note says where it landed |
| `snapshot --task N\|final --label "..."` | Records the working tree as a fix baseline and prints its tree id, for a fix outside triage (executing-plans). `triage` takes an SDD or close fix's baseline itself |
| `close-round --note "..."` | Starts the completion close and prints the HEAD its gates review. Refuses when the store already holds a close (an unfinished one resumes at triage; a finished one is final, and a new close needs a cleared store), and while any disclosure or question is open or a task-note waits on a task that never completed. Its rounds are counted by `triage --task close`. The retired round-number flag fails with the new usage |
| `check <record-path>` | Validates a record an agent just wrote and appends its summary to the check history. It enforces each role's contract, including a finding's severity, reach, rule and sites, a re-check's answer to every forwarded contest, a fixed finding raised again unchanged (one the user dropped or filed may be; `reopens` must name a settled finding and sit in code changed since), a coder's shared symbol listed twice, a `handed_off` coder with no other coder named in `handed_to`, a fix record (a `handed_off` share included) without its baseline or below its round's cycle, and, on a finished fix, the sweep rows, tests first, decision rows and test changes the round required |
| `clear [--discard-open]` | Deletes the run's records, handoff files and logs, and every scratch copy and build cache its reviewers left. Refuses while follow-ups, disclosures or questions are open, unless the user confirmed the loss |

## Reading the working tree

| Command | What it does |
|---|---|
| `diff-since <tree> [<path>...]` | The diff since a snapshot tree, new files included, limited to the task's files |
| `labels <tree> [<path>...]` | Lists review-process labels (task and finding ids, cycle numbers, commit hashes) on lines added since the tree; exits 1 if any |
| `scratch --task N --agent <name> [--remove]` | Makes a throwaway worktree of the working tree as it is now (uncommitted edits and new files, not ignored files or edits inside submodules) for a quality reviewer's break check, one per task and reviewer. It lives in the system temp folder, in a folder only this user can write to, never in the repo or the store, so a build cache never lands in a synced folder. Prints its path, then a `CARGO_TARGET_DIR=` line naming the copy's own build cache. The checkout is never touched. `--remove` deletes the copy and keeps the cache for a re-check; the task's commit deletes both, and `clear` deletes every one the store left |

`task_brief.py`, beside it, builds each task's brief from the plan, embeds the task's notes from the store, logs their delivery, and records the plan in the store once (what `run-state` judges against). With `--spec`, it refuses a plan without a `Spec coverage: <that spec> — pass (<report>)` line (or a `user ruling:` form) whose report exists, the record of lean-plan's coverage check. It refuses a task whose `Verify:` line has no backticked command, whose `Cases:` still carries an `open:` row, or whose `Cases:` has a row that doesn't separate its situation from its expected result with `→` or `->`. A row may group cases (`size=0, size<0 → ValueError`), and `n/a — <reason>` and the refactor form (`preserves <behavior>; covered by <tests>`) are exempt. It also opens the brief with the task's rigor level, and refuses a task `Rigor:` line below the project level.

`rigor.py`, beside it, resolves the test rigor level (see `rigor.md` in the skill directory for what each level changes). It reads tracked files only and writes nothing.

| Command | What it prints |
|---|---|
| `rigor.py [--repo DIR]` | The project level and its reasons, e.g. `standard: 4,200 source lines (python); numpy +1` |
| `rigor.py --plan PLAN --task N` | Task N's level: the project level, or the higher one its `Rigor:` line sets |
| `rigor.py --plan PLAN --store STORE --files` | The project line, then `<level> <path>` for each file a raised task's latest stage footprint lists |

It exits 2 on a `Test rigor:` value in `CLAUDE.md` that isn't a level, or a task `Rigor:` line below the project level or naming no level.
